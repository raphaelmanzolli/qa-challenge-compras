# BUG-005 — Busca textual q deixa de restringir compras ao combinar filtro por status

- **Estado:** aberto; reproduzido por API-10 em 26/10/2026.
- **Fonte:** parâmetro `q` de `GET /api/compras` no contrato fornecido.
- **Ambiente:** Linux, imagem `qa-challenge-compras:1.0`, Playwright API, comprador autenticado.
- **Severidade:** média. **Prioridade:** P2.

## Reprodução

1. Autenticar como comprador.
2. Criar uma compra com termo único no objeto, como `QA busca {UUID}`.
3. Criar outra compra sem esse termo. Manter ambas em RASCUNHO.
4. Consultar `GET /api/compras?q={termo}`, codificando o termo como parâmetro de URL.
5. Repetir com `GET /api/compras?q={termo}&status=RASCUNHO`.

**Esperado:** as duas consultas retornam somente a compra correspondente ao termo.

**Obtido:** a busca sem status retorna somente o ID esperado. Com `status=RASCUNHO`, a resposta inclui compras cujo objeto e código não correspondem ao termo.

**Evidências:** [controle sem status](../../resultados/automacao-2026-10-26/API-10-busca-sem-status.json), [busca com status](../../resultados/automacao-2026-10-26/API-10-busca-RASCUNHO.json) e [execução](../../resultados/automacao-2026-10-26/execucao-integral.json). As respostas foram preservadas completas.

**Impacto:** o comprador recebe resultados que não atendem à busca. Não foi demonstrado acesso indevido ou alteração de registros. A falha observada está na combinação dos filtros; a causa interna não foi investigada.

**Reteste:** `npx playwright test tests/api/consultas.spec.mjs`. A conferência da busca pela interface não faz parte desse teste.
